## 2. inode: 怎么装下比一个块大的文件

一个块 512 字节, 一个文件可能有 100 KB 甚至更大。磁盘上的 inode
负责记录一个文件的所有数据块位置:

```c
/* 磁盘上的 inode (64 Byte) */
typedef struct dinode {
	uint16 type;                   /* T_DIR / T_FILE / T_DEV, 0 = 空闲 */
	uint16 major, minor;           /* 设备号 */
	uint16 nlink;                  /* 硬链接数 */
	uint32 size;                   /* 文件大小 (字节) */
	uint32 addrs[NDIRECT + 1];     /* 数据块号 */
} dinode_t;
```

**addrs[] 是索引表**, 分成两部分:

- `addrs[0..11]`: 12 个直接块 -> 12 × 512 = 6 KB

- `addrs[12]`: 一级间接块 -> 128 × 512 = 64 KB

一级间接块里存的是**块号数组** (一个块能放 `BSIZE/sizeof(uint32)` 个块号),
不是数据本身:

```
   addrs[12] ──► [ 块号 ][ 块号 ][ 块号 ] ... (128 个)
                     │
                     └──► 真正的文件数据
```

真实文件系统会用二级、三级间接块 (ext2) 或 extent/B 树 (ext4),
本次实验实现到一级间接块为止。

### 2.1 inode_block_map: 逻辑块号到物理块号

`inode_block_map` 把**逻辑块号** `bn = 文件内偏移 / 512` 转译为**物理块号**:

```
   bn < 12               -> 直接块: addrs[bn]
   bn < 12 + 128         -> 间接块: 读 addrs[12], 取其中的 [bn - 12]
   bn 超出 (alloc = 1)    -> 分配新块
```

三个容易出错的地方:

1. **边界**: `bn == 12` 应该走间接块的第一项, 而不是 `addrs[12]` 本身

2. **分配间接块时**: 如果 `addrs[12]` 还是 0, 要先 `balloc` 分一个新块,
   并且**把这个块清零** (里面是随机数据, 不清零会被当成有效块号)

3. **分配数据块时**: 新块要清零, 否则文件会"自带"一段垃圾数据 ——
   这是经典的信息泄露 (上一个文件的内容被下一个文件读到)

### 2.2 inode_read / inode_write

两者结构对称, 都是"按块循环搬运":

```
   while (还有字节) {
           bn = off / BSIZE                       /* 逻辑块号 */
           pa = inode_block_map(ip, bn, alloc)    /* 物理块号 */
           把 (off % BSIZE, 本次长度) 这段数据搬到/搬出块缓存
           off += 本次长度; n -= 本次长度
   }
```

两个必须处理的细节:

- **`is_user` 参数**: 为 1 时目标/源是**用户地址**, 必须走
  `uvm_copyin` / `uvm_copyout`; 为 0 时是内核可以直接访问的地址。
  选错了不会编译报错, 但会读到垃圾或者内核缺页。

- **一次读写可能跨块**, 所以要用 `min(剩余, 块内剩余)` 算出本次长度。

**inode_read 必须通过 bread / bwrite / brelse 访问磁盘, 不能直接调用
block_read**。绕过缓存的直接后果是: 文件系统通过 bread 改了块 X
(还在缓存里没写回), 你再通过 block_read 读块 X, 读到的就是**旧的**内容,
缓存与磁盘在这一刻失去一致, 而症状会出现在完全无关的地方。

### 2.3 inode 缓存与生命周期

inode 不是每次用都从磁盘读 —— 那样每个文件操作都要读磁盘。
`inode_init` 建立 inode 缓存, 并放入 `fs_init` 的合适位置。
`inode_get(inum)` 先在缓存里找, 找不到才读磁盘:

```
   inode_get:  ref++      "我正在用这个 inode"
   inode_put:  ref--      "我用完了"
               ref == 0 && nlink == 0  ->  真正删除它
```

`nlink == 0 && ref == 0` 才删除, 这是 Unix "删除正在使用的文件"
语义的核心: unlink 只是把链接数减到 0, 文件要等最后一个使用者
关闭它才真正消失。磁盘上的 inode 与内存中的 inode 通过
`inode_rw` (或 iupdate/iload) 互相更新。

## 3. dentry: 目录也是文件

Unix 最优雅的设计之一:

**目录就是一个内容为"目录项数组"的普通文件。**

```c
/* 目录项 */
typedef struct dirent {
	uint16 inum;            /* inode 号; 0 表示这一项空闲 */
	char   name[MAXNAME];   /* 文件名 (定长, 不保证 '\0' 结尾) */
} dirent_t;
```

于是路径解析变成一个循环: 从根目录开始, 在它的内容里查找一个名字,
拿到 inode 号, 再在下一级里找。**你不需要为目录发明任何新的存储机制** ——
用同一套 `inode_read` / `inode_write` 就够了。

### 3.1 dir_lookup

- 逐项读目录内容, 比较名字。名字比较必须**精确** (不能只比前缀,
  否则 `/test_1` 会匹配到 `/test_10`)

- 目录项有固定长度, 第 `i` 项的偏移是 `i * sizeof(dirent_t)`

- 遇到 `inum == 0` 的空项要跳过, 不能当成"文件结束"

### 3.2 dir_link

- 先 `dir_lookup` 确认名字**不存在** (否则会创建重复项)

- 找一个空项写入; 如果没有空项, 要**扩展目录文件** (给它分配新块)

- 成功后 `inode->nlink++`

**两个操作都必须持有目录 inode 的锁** —— 否则两个进程同时创建
同名文件会得到两个都"创建成功"的结果。

### 7.1 日志：让文件系统在崩溃后仍然一致

**为什么值得做**：现在一次"创建文件"要改很多处磁盘结构（位图、inode、目录项）。
中途掉电就会留下不一致：位图说块已被占用、inode 里却没有它。
日志用"先写日志、再写原地"把多步更新变成一次原子提交——这是真实文件系统的核心机制之一，
做一遍你就明白为什么它值得牺牲一半写入带宽。

**思路**：
- 磁盘上加一块日志区（镜像工具负责划分，超级块记录位置与长度）
- 用一个"事务"包住一次系统调用里的所有块写：先把将被修改的块写进日志，
  再写一条**提交记录**；提交成功后才把日志内容写回它们真正的位置，最后清掉日志
- 挂载时检查日志：有已提交的事务就**重放**（把日志内容写回原位），没提交就丢弃
- 只做**元数据日志**就已经能解决大部分不一致（数据块不进日志），先别贪
- 三个关键点：提交记录必须**最后写**且带校验（序号或校验和）；
  日志满时要阻塞新事务（不能覆盖未提交的内容）；重放必须幂等（重复挂载安全）

**怎么算做到**：做一个对比实验——在"改了位图还没改 inode"的时刻强制重启（杀掉 QEMU），
没有日志时文件系统挂载后出现不一致，有日志时能自动回到一致状态；
正常读写路径的功能与性能损失可接受。

**涉及**：`kernel/fs/fs.c`、`kernel/fs/inode.c`、`kernel/fs/bitmap.c`、`tools/mkfs/mkfs.c`　**难度**：★★★

### 7.2 VFS：把文件系统抽象成可挂载的接口

**为什么值得做**：现在头文件里直接声明的是"我们这套实现"的 inode/目录操作，
路径解析也直接调它们——换一套文件系统就得改路径解析。
VFS 用一张操作表把这些调用变成可替换的实现，`mount` 变成"把某套实现挂到某个挂载点"。
它是"抽象是否成立的最终检验"：做完之后，加一套新文件系统应该**不用改路径解析**。

**思路**：
- 定义一组**窄**接口（挂载/卸载、按名查找、创建、读、写、列目录、删除、取属性），
  只放真正会被调用的，不要照抄真实内核的宽接口
- 把现有实现包装成第一套实现；`inode` 要么在接口里通用化（最小公共字段 + 私有指针），
  要么彻底留在实现内部——两种选择各有利弊，先想清楚再动手
- 挂载表：路径 + 该点的实现 + 该文件系统的私有数据；路径解析时按**最长前缀匹配**
  找到挂载点，跨挂载点的路径（`/mnt/a/b`）要能走通
- 用一套最简单的"内存文件系统"验证抽象：它没有任何磁盘结构，
  如果它需要你改路径解析，说明接口还没抽干净

**怎么算做到**：现有测试全部照常通过；把内存文件系统挂到某个目录后能创建/读写文件；
跨挂载点路径可解析；`mount` 列表能在 shell 里打印出来。

**涉及**：`include/kernel/fs.h`、`kernel/fs/fs.c`、`kernel/fs/dentry.c`、`kernel/fs/inode.c`　**难度**：★★★

### 7.3 统一的 page cache

**为什么值得做**：现在每次读文件都走"块大小（512 字节）"的缓冲，大文件读被块粒度限制，
而且"块缓存"与"文件视角"是两套东西。page cache 以**文件页**为单位缓存，
与"文件映射进地址空间"天然配套，也把 lab-7 的块缓存放到它该在的位置（它的下层）。

**思路**：
- 缓存挂在 inode 上：键 =（inode 号，页号），值 = 一个物理页 + 有效位 + 脏位
- 读写先进缓存：未命中时通过下层的块接口把**一整页**组装出来（多次块读）
- 三个要想清楚的点：**部分页写入**（不足一页的写要先读上来再改）；
  **脏页何时写回**（退出时？定时？缓存压力大时？）；**共享**
  （缓存挂在 inode 上，所以同一文件多次打开共享同一份缓存——这正是它与"打开偏移量"的区别）
- 有余力就和 lab-5 的文件映射（mmap 与 lazy-alloc）接起来：映射一个文件区间时直接把它登记到地址空间，
  缺页时再从 page cache 拿页

**怎么算做到**：顺序读一个跨一级间接块的大文件时，块读次数显著下降（打印统计）；
同一页重复读命中缓存；写入后重新挂载内容正确；缓存大小有上限且能回收。

**涉及**：`kernel/fs/inode.c`、`kernel/fs/bio.c`、`include/kernel/fs.h`　**难度**：★★★
