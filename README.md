### 3.1 第一阶段：物理内存

首先关注链接脚本。镜像的代码、只读数据、可写数据、BSS 和每核栈一直被内核占用，不纳入动态分配。只有 `kernel_end` 到 `DRAM_BASE + DRAM_SIZE` 可以管理，起点向上按页对齐。

基本原理是 **4KiB 物理页切分 + 空闲链表组织**。前 1024 页为内核池，其余为普通页面池。`regions[0]` 和 `regions[1]` 分别记录起止地址、锁、空闲计数和链头。

不需要与页面数量一样大的节点数组：空闲页的头部就是 next 指针，分配出去后整页归调用者使用。

```text
init → 建立区域与空闲链表
alloc → 持锁摘下页面，更新计数，清零后返回
free → 检查地址，持锁归还页面
```

初始化只执行一次；访问共享链表必须加锁。`pmem_alloc(true)` 使用内核池，`false` 使用普通池。与旧版耗尽即 panic 不同，本版耗尽返回 NULL，让调用者决定如何处理。释放须检查对齐、区域归属和重复释放。

### 3.2 第二阶段：内核态虚拟内存

串口资源没有区别，内存却被细分成许多通过地址区分的页面。我们需要记录地址之间的对应关系，并让 MMU 自动翻译。

Sv39 的每级页表有 512 项，三级索引各 9 位，加上 12 位页内偏移。PTE 记录物理页号和标志位；有效且 R/W/X 全零的项指向下一级页表，叶项指向实际数据页。

按 `walk → map → unmap → kvm_init` 的顺序实现。`walk` 只负责寻找叶 PTE，需要时分配中间表；映射要求 va/pa 对齐、长度非零，最后不足一页向上覆盖，拒绝重复映射、范围溢出和 W 无 R 的非法权限。有效叶项设置 A/D，避免依赖硬件自动更新。

`unmap` 清除叶项；`free_pages=true` 只用于归还普通池数据页，不用于设备映射或内核镜像。`vm_print` 已提供，用它查看三级结构。

内核使用恒等映射：代码 RX、只读数据 R、其他内存 RW、UART RW，不给内核映射设置 U。不要映射固件保留区。此时不引入中断控制器映射。

### 3.3 接入启动流程

在自己 lab-1 的主核初始化里，打印初始化后调用 `pmem_init()`、`kvm_init()`，然后再发布初始化完成标志。每个 CPU 在观察到该标志后调用教师提供的 `kvm_inithart()`，最后继续打印/等待。不重新编写或替换以前的锁与打印。

## 4. 测试

```bash
make build
make run
make CONFIG=riscv64-visionfive2-uboot image
```

先做物理内存测试，再打开分页；不要同时排查两个阶段。

1. 两核各申请 512 个内核页，写入不同内容，等待双方完成后并行释放。检查页地址不重复、对齐且在对应池中。
2. 普通池申请 10 页，记下空闲数，写入 0xAA、释放再申请，检查全页清零及计数恢复。
3. 耗尽两池，确认返回 NULL；释放后重新分配。非法地址和重复释放应明确报错。
4. 新建页表，将页面映射到 `0x8000`、`0x100000`、跨二级/三级索引的位置和 `VA_MAX-PAGE_SIZE`，用 `walk` 核对 PA 与权限。
5. 解除映射后检查 V 清除；测试重复映射、越界和未映射区域。打印修改前后的页表。
6. 两核启用内核页表后仍可输出；尝试写入只读页时应进入早期异常停车点，可用 GDB 查看 PC。

临时测试结束后从正常启动中移除。编译框架不代表上述运行测试已通过。

## 5. 课后实验

- buddy 分配器：支持连续多页分配，比较碎片和管理成本。
- 内核堆：在页分配上建立小对象分配接口。
- 大页支持：为页表加入更大粒度映射，比较页表开销。
